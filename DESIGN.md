# Design system

Implementation direction inferred from the approved settings-tool brief, not separately aesthetically approved.

Neutral workspace: off-white main surface and quiet sidebar, deep green primary action, restrained 6px corners and hairlines. System UI typography for controls (not a branded marketing display face). Light/dark follow OS. No gradients, decorative metrics, or icon-card grids.

First viewport: identity and current scope, searchable section navigation, actual editable settings, provenance and clear save action. Two-column label/control rows on desktop collapse into stacked rows on phones. Sidebar becomes a native section selector at narrow widths. Content is the product, not a hero.

Interaction signature: staged changes expose an explicit review list before writing native Pi files. Changes are not auto-saved. Errors remain alongside an intact draft. Async outcomes are announced via live regions. No entrance animation required for a frequently used settings tool.
